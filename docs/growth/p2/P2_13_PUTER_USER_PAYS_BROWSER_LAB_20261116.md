# SLBI P2-13 — Puter.js browser image lab, owner-only production route

## Why this route differs from the initial Preview

- The owner experienced Vercel Preview login blocked: Preview lacked `NEXT_PUBLIC_CLOUDFLARE_TURNSTILE_SITE_KEY` and `CLOUDFLARE_TURNSTILE_SECRET_KEY`; password-login correctly fails closed rather than bypassing Cloudflare.
- Vercel environment inventory confirmed Turnstile credentials configured **Production only**. Adding an unrelated bypass or copying the Production secret to shared Preview branches was rejected.
- **Resolution**: use the existing secure Production login/Turnstile on `https://www.slbusinessindex.com`, then protect the new experimental nested route with the **same current verified internal QA entitlement** used for the owner's Poster Studio. A read-only Supabase query confirmed the owner's QA grant exists and is active before implementation. No new account permission, database mutation or login bypass.
- `app/vendor/marketing/design/puter-lab/layout.tsx` validates `auth.getUser()` and `isPosterInternalQAAccount(user.id,client)`, with 404 for other signed-in users; parent Poster Studio layout already checks Pro/approved staff review. The trusted entitlement marker is sourced from RLS-scoped database, not client metadata or hardcoded email.
- **Do not edit** `app/login/page.tsx`: the Preview-specific warning patch was reverted to exact main contents. No production auth/Turnstile behavior change.

## Browser integration

- Route `/vendor/marketing/design/puter-lab`, only reachable by the existing internal QA owner account. Not linked from general marketing/navigation.
- `https://js.puter.com/v2/` is loaded on the client. Puter account sign-in occurs on a button click. **No API token/key needed**, and do not expose private Vercel secrets to browser code.
- Official image model IDs reverified against https://developer.puter.com/tutorials/free-unlimited-image-generation-api/ (updated 2026-11-13):
  `openai/gpt-image-2.6-flare`, `google/gemini-3-pro-image`, `black-forest-labs/flux-2-pro`, `qwen/qwen-image`. The last is not verified as Qwen Image 2.1. Earlier branch used incorrect Gemini preview and Qwen 2.0 IDs; these were corrected.
- Default `test_mode:true` returns **sample image**, not actual model output, at no AI inference credit. For genuine generation the owner must explicitly enable real mode, acknowledge that **their own Puter User-Pays allowance or balance may be charged**, and click. Do not trigger automatic requests.
- Experimental generated bytes are transient client preview only; no Supabase job, no persistent image upload, no SLBI wallet charges. Current backend `SLBI_POSTER_IMAGE_PROVIDER=cloudflare`, Gemini, 8 Growth Credit user workflow, image generation quota, private poster storage all unchanged. The experiment is NOT the release of a new production image provider.
