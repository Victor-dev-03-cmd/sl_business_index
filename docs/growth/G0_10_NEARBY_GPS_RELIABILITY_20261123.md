# G0-10 addendum — Nearby GPS correctness / Android and iOS browser reliability (2026-11-23)

**Status:** Engineering candidate. PR / CI to be verified. Actual physical location accuracy cannot be certified by mock tests. No production Supabase SQL migrations, Vercel Preview requests, new paid providers or service-role exposure.

## User-reported regression and confirmed code causes
- Nearby initial state previously used hard-coded Colombo coordinates `6.9271,79.8612` with label `Colombo · Starting area`, falsely suggesting current location even when user was somewhere else in Sri Lanka.
- Nearby `getCurrentPosition` used `enableHighAccuracy:false`, timeout 8000 ms and max cached age 60000 ms. Home used low-accuracy, timeout 5000 ms and its own unrelated 6000 ms spinner timer. These can yield low-quality IP/Wi-Fi fixes, timeout on slower phones and inconsistent UX.
- Nearby errors all collapsed to one generic message; no permission denied, GPS off, timeout or approximation guidance. Desktop may lack GPS hardware; no web application can override incorrect/denied device/browser geolocation.
- Nearby query automatically broadened user GPS search up to 50km on empty results even if user selected a smaller radius.

## Proposed architecture in this candidate
1. `lib/location/precise-geolocation.ts` is shared by Home and Nearby. Native browser Geolocation API only over HTTPS or secure context. Requests begin directly on a user gesture. `enableHighAccuracy:true`, `maximumAge:0`, initial timeout 18s, bounded watchPosition refinement 8s when the initial fix is coarse, absolute watchdog 30s, abort cleanup. Reject invalid/older-than-2-min/over-2000m-accuracy positions; never silently accept IP-based Colombo. Error classes and messages: insecure, unsupported, denied, unavailable, timeout, inaccurate, invalid, cancelled. All Nearby GPS requests require an explicit user tap. Headless WebKit reported `granted` but stalled on a page-load request; disabling automatic reacquisition avoids that race and preserves the reliable Safari user-gesture path.
2. `app/nearby/NearbyExplorer.tsx`: default map centers Sri Lanka for browsing, clearly labeled **Choose your area** rather than claiming Colombo. With no location/query, nearby RPC is disabled and an explicit GPS/town choice card appears. If a keyword is given without a location, results can be island-wide and are labeled accordingly, never claimed local. Accurate user-approved GPS coordinates drive server RPC distance query and map marker, with visible ±accuracy. For kind GPS, `dist_limit` uses the selected radius exactly. Existing manual town/district and Hybrid/Semantic search remain intact.
3. `app/HomePageClient.tsx` and `MobileHomeExperience.tsx`: shared precise request and informative error UX on Home and Nearby entry. Do not send GPS fix to third-party geolocation API or persist in localStorage. Existing intentional Nearby URL coordinates remain; review URL privacy separately before changing the established deep-link contract.
4. `tests/location/precise-geolocation.test.mjs` (Bun) covers accurate GPS, coarse fix refinement, rejection of IP/invalid/stale, permission error codes and cancellation. `tests/g0/browser/nearby-location.spec.mjs` runs Chromium with Playwright browser geolocation and WebKit with a deterministic injected synthetic provider (because GitHub headless WebKit native provider stalled); physical iPhone permission/GPS remains unproven and checks missing-location CTA / synthetic accurate fix; no real device GPS.
5. Workflow paths for G0 foundation / browser QA include new files. Existing UI/search and DB features otherwise unchanged.
