# SLBI shared desktop/mobile UI/UX development reference
Owner direction 2026-11-22. Preserve desktop and native-style mobile web layouts; the responsive presentation/navigation can differ but core business functionality, API contracts, auth/entitlements, input validation, database queries, event semantics, state transitions and billing must be shared. Fix actual logic issues in the shared service, not separate device-dependent implementations. No redesign of owner-approved mobile UI to satisfy outdated tests. Keep NotificationBell, theme, profile and desktop-only live analytics; LiveCounter hidden at mobile breakpoint. Existing Discovery and marketing routes preserved. Native app releases, if separately shipped, require API-version compatibility, not assumed identical code.

## Stability rule
Once a phase reaches documented acceptance, freeze its public contracts and keep regression tests as gate for later phases. No speculative rework. Necessary evidence-backed security, data integrity, compatibility or regression fixes remain permitted through versioned changes, review, test, migration/rollback plan where applicable; reopen the affected gate if a regression invalidates acceptance. Do not freeze known defects or pretend the foundation can never require maintenance.
