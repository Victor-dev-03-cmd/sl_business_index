# WA-01 — NeuroGrowth Secure Agent Orchestrator & Approval Contract
Date: 2026-11-25. Scope: **executable synthetic-only security foundation**, not a live WhatsApp, publishing, marketing-email or cross-dashboard executor.

## Product contract from owner
User's permanent North Star is **WhatsApp-first, one-request, all-owned-vendor-tools AI operator**: a vendor can say in Tamil/Sinhala/English “prepare Christmas promotion poster, social posts and email”; agent securely reads their own GrowthOS and Marketing Studio/allowed Settings, prepares editable poster/caption/email/calendar previews, sends the actual image and copy to their verified WhatsApp account, asks granular and final approvals, executes only exact authorized actions, and returns real provider-confirmed summary in WhatsApp or optional dashboard. A new isolated chatbot that merely answers questions does NOT fulfill the goal. Canonical [North Star](NEUROGROWTH_WHATSAPP_VENDOR_AGENT_NORTH_STAR_20261125.md). WA-01 lays the AUTHORIZATION CONTRACT; the WhatsApp/LLM UI and external connectors come in later phases.

## Implementation on `feature/neurogrowth-wa01-secure-orchestrator-20261125`
- `lib/growth/agent/wa01-orchestrator.mjs`: executable server-side-design JS module (Bun-compatible via `node:crypto`), **no API/client**. Versioned unified capability registry lists owned profile, GrowthScore, CRM, reviews, analytics, brand, marketing/campaigns/calendar, safe Settings and provider metadata as **read candidates**; poster/caption/campaign/email/Settings suggestions as **draft-only**; Facebook/Instagram/email as proposed external actions; blocked billing/security/account delete, verified badge override, arbitrary DB and customer WhatsApp broadcast.
- Structured request and action exact-shape allowlists: rejects extra fields (PII, hidden provider accounts), wrong owner, unowned business, invalid verified WhatsApp session binding, missing connected provider capability, stale consented email audience or unsubscribe status, changed audience count/hash, duplicate IDs, unknown tools, malformed media/creative hashes, cost-over-budget, and invalid/expired schedule.
- `prepareWA01Manifest`: requires a **server-verified owner context** supplied by a future authenticated backend, bounded action list (max12), 30-minute manifest expiry, content and preview SHA-256, selected business and linked-channel ID, exact connected account/recipient consent snapshot and explicit **LKR or USD minor-unit currency** plus maximum cost (currency is included in the signed manifest). Computes canonical SHA-256 over all approved fields. Returns private preview descriptors; never sends media/messages.
- `issueSyntheticWA01Approval`: **test-only simulated** vendor-issued item/final HMAC receipt (nonce, expiry max5min, plan/version/owner/business/channel/content digest and interaction ID). Only used to prove concept in tests: boolean `verifiedByServer` is MOCK, **not an authorization mechanism**, never use this issuer as a production approval endpoint without validating signed Meta webhook identity or fresh logged-in owner interaction and persisting approvals.
- `evaluateWA01DryRunQueue`: checks separately signed item approval **AND final plan approval** for the exact revision, owner, business, channel, action and manifest. It rechecks provider account and consent state at decision time and requires an **injected atomicClaimOnce** callback. No callback, error, duplicate/old nonce or changed plan => fail closed. Final manifest receipt can apply to several individually preapproved actions, never automatically approve skipped/edited/unseen ones. **Always returns `synthetic_dry_run_queue_candidate` with `externalDispatchPerformed:false`, never invokes a provider.** An in-memory Set in tests is NOT a durable or cross-region replay ledger; production requires a DB transaction/unique constraint plus durable outbox and idempotent provider retry.
- `lib/growth/agent/wa01-orchestrator.d.mts`: typed interface for a future server integration.
- `tests/ml/neurogrowth-wa01-orchestrator.test.mjs`: executable Node 22 negative/positive synthetic tests for complete owned tool map, cross-tenant denial, PII-injection, account connection, consent, content/version binding, item vs final approval, tamper/expiry, race/replay and same-manifest distinct approvals.
- `.github/workflows/neurogrowth-wa01.yml`: dedicated ephemeral no-secret Node 22 syntax and actual test execution.
- **14 executable WA-01 Node tests** cover real dry-run code, not static source matching; currency changes after approval invalidate the receipt. Node and Bun-compatible source; live provider auth remains unavailable.
- Existing `lib/growth/agent/capabilities.ts` (ML-01) remains untouched and continues deny-default design. WA-01 augments it but does not assume an active permission executor or connect all vendor data.

## Security truth and operational blockers
- Nothing authenticates real WhatsApp messages, maps Meta identities to an SLBI owner, reads real vendor tables, creates or saves drafts, renders actual posters, calls social/email providers or moves money. No Postgres/Neon/Supabase migration, no service role, no customer data, no paid GPU, no Meta token.
- The `serverContext` in WA-01 is purely an **injected TRUSTED server contract**. Mock tests populating owner, verified link, OAuth and consent arrays DO NOT establish actual production validity. All provider connector entries in `lib/marketing/engine-registry.ts` remain planned, not connected merely because they appear in this registry.
- The HMAC test issuer and injected atomic callback demonstrate safe contract behavior; before any real launch, require signed Meta webhook, phone/business link owner verification, rate limits and nonce database, true per-provider OAuth status, digital asset byte hashes, time zone/holiday confirmation, full audit trail, exact-idempotent outbox, email recipient consent/suppression and policy compliance. A chatbot or model output can NEVER sign approvals.
- Need current official WhatsApp Business Platform AI-provider/product eligibility decision for this business-specific Sri Lankan operator, consent, templates, 24h messaging rules. Do not use unofficial WhatsApp libraries.
- Proposed `send_email` has only a **verified-email** placeholder provider family in WA-01; real Google/Microsoft or approved domain adapters require separately approved scope, token vault, entitlement and consent review. Never promise immediate external sending.
- Every synthetic candidate's “ready” does NOT mean authorized to publish; after future auth RLS and transactional replay/outbox implementation, a separate real dispatch gate must be tested.
- Existing ML-01–ML-06 numerical experiments are NOT a vendor conversational AI or real growth-revenue model. Numeric ranker cannot self-authorize multi-tool mutations.
