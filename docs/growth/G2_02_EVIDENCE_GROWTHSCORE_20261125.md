### Model and honest scoring contract
- Pure `lib/growth/g2/growth-score.ts`, version `g2-growth-readiness-v1`; 13 actionable observed fields, **100 weighted possible points**, no paid-plan, subscription, verified badge, analytics views, credit wallet or sales bias.
- Weighted dimensions:
  - **Listing content: 40** — name 5, category 5, description 12, services 10, gallery photos 8, all from the already owner-verified G1 read-only Knowledge.
  - **Contact & discovery: 40** — phone 10, business address 10, plausible map location 10, opening hours 5, valid http(s) website 5, from `businesses` under owner id/status RLS.
  - **Business identity: 20** — logo 8 from same owner listing, brand name 6 and languages 6 from G1 vetted allowlist.
- Factual **present/ready** earns item's weight; observed missing creates a specific edit task; withheld/unavailable is explicitly EXCLUDED from observed denominator, never turned into zero. Coverage = observedWeight/100. Numeric score = round(100*earnedWeight/observedWeight) **only if coverage ≥75%**, otherwise `score:null` and `Insufficient data`. Domain also returns per-dimension score+coverage. Unknown can result in a high provisional score WITH visible incomplete coverage, never silently called complete.
- `recommendations` are only **observed missing** fields, deterministic descending readiness weight then key, with existing working owner routes `/vendor/my-businesses/<businessId>/edit`, `/vendor/gallery-services?business=<id>`, and `/vendor/marketing/brand?business=<id>`. No AI, fictional conversion optimization, guaranteed search rank/revenue or auto-generated content. Score is **readiness**, not real-world growth/outcome validation.

### Live read-only infrastructure
- `app/api/vendor/g2-growthscore/route.ts` GET validates UUID, uses cookie-bound Supabase SSR `createClient` + existing G1 `resolveG1ReadOnlyKnowledge`, which authenticates `auth.getUser()`, validates approved `businesses.owner_id` and RLS BEFORE reading brand/profile. G2 then RE-CHECKS `auth.getUser()` and selects exact allowlisted contact columns with `eq('id',businessId).eq('owner_id',user.id).eq('status','approved')` under same RLS client. No service role, admin adapter, random user ownerId, RPC, writes, schema migration or caching across users. Uniform unknown/foreign/unapproved `404`, sources failing `503`. `Cache-Control: private, no-store`, `Vary: Cookie`. **Only computed score, signal labels/links/source and boolean presence are returned, NEVER raw phone/address/coordinates/customer rows**.
- `lib/growth/g2/contact-evidence.ts` transforms already-owner-scoped business row into boolean presence; valid map pin restricted to Sri Lankan approximate bounding box (not fake 0,0), URL requires http/https; no value text exposed. An unavailable source gives 503, not false missing.
- `app/vendor/components/G2GrowthScorePanel.tsx` shared responsive Orange/Black/White mobile-first UI: 0–100 or `—`, visible evidence coverage %, 3 domain bars with data-source counts, up to 4 actionable exact-business links, safe loading/error/retry, no hidden writes or polling. It uses normal existing TanStack Query keyed by owned businessId, credentials same-origin, no-store, response version/id validation, 60s stale.
