## Live production read-only function inspection
- `public.get_or_create_direct_room(other_user_id uuid, p_business_id uuid)` is `SECURITY DEFINER`, callable by `authenticated` but not `anon`, **no pinned search_path** in the observed live snapshot.
- Function uses `auth.uid()` as caller, finds an existing exact two-member direct room or inserts `chat_rooms` and `chat_room_members` for the caller and arbitrary supplied `other_user_id`. It does **not verify** that `p_business_id` is approved nor that its owner is one of the two participants. User-supplied business association could therefore be inconsistent with tenancy. This is a code-level security boundary gap, **not evidence of exploitation**, and we performed **no production invocation**.
- Live catalog confirms `businesses.owner_id`, `businesses.status`, `chat_rooms.business_id`, and `chat_room_members.user_id` and their FK/unique structure. RLS is enabled on all three tables but a definer function can bypass RLS; table RLS alone is not enough.

## Implementation, in the repo only
- `docs/growth/g0/candidates/CHAT_DIRECT_ROOM_TENANT_GUARD_REVIEW_ONLY.sql` preserves the existing RPC signature but adds: non-null `auth.uid` + other distinct user, published `businesses.status='approved'`, the business owner must equal one of the two participants, `SET search_path=''`, and a stable unordered pair/business-scoped transactional advisory lock before find-or-create. Existing businessless direct-message mode is retained for backward compatibility; it still permits unsolicited user-to-user requests and needs separate abuse/privacy product review.
- `tests/g0/chat_tenant_boundary.sql` creates only synthetic users/businesses/rooms in a disposable PostgreSQL 17 database, revokes anon RPC execution in its fixture, runs authenticated positive, duplicate and reverse participant tests, denies pending/unowned/missing business, self-target/null user/missing JWT and checks rejected calls did not create rows. Script wraps fixture in a transaction and rolls it back.
- G0 Foundation CI adds an explicit `chat` matrix domain and runs the disposable test; existing marketing, Nearby/Search, public RPC, billing, review, backup and all production behavior unchanged.
